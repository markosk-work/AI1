## (c) Good practices, useful to me


**Power Fx and canvas** (`pp-powerfx`):



- Use App.Formulas for named constants, `Type()` definitions and pure functions, with no `Set`/`Patch`/`Navigate` there.

- Behaviour functions make exactly one `Flow.Run` and return a typed value or raise `Error()`.

- Handle errors centrally in `App.OnError`.

- Only adopt a result if it is not blank, and don't `Set(g, Udf())` blindly.

- Compare IDs with GUID constants.

- Use AutoLayout with `FillPortions` and `LayoutMinWidth`, and test the phone layout.

- Traps: `If` branch types must be compatible, a classic Toggle's `OnChange` fires on code changes, and wrong YAML node placement breaks Studio.

- Gates: `check-pa-yaml.mjs`, `pac canvas validate`, then the App checker showing Formulas (0).

- Keep Studio's format and don't hand-edit `Controls/*.json`.



**`pa-yaml-editing.md`:** surgical edits, preserved line endings, and formulas written with `=` or `|-`.


**Flows:**



- Take the caller from `x-ms-user-id` and don't trust a client-supplied user.

- Use a `{data, error}` response contract and remember that a green run proves nothing.

- `retryPolicy: none` on mutations, and an explicit `timeZone`.



**SQL:**



- Always `THROW`, and use scalar parameters.

- Use GUID IDs and lookup tables instead of string enums.

- Add a concurrency token, and watch for NULL in string concatenation.

- Mirror the nearest sibling, make the smallest change, and never rename deployed objects.

- Dry-run in rolled-back transactions.



**Testing and diagnosis:**



- Test as a plain user, prove changes with data rather than screenshots, and restore what tests touched.

- Reproduce a bug before fixing it.

- Separate database time from connector time.

- Read-only first, then report cause, evidence and owner.
